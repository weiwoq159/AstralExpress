字段与交互对照

供实现 Library.tsx 时参考——数据全部来自 useToolStore 已缓存的 Manifest[]，搜索 / 筛选都在前端本地过滤，不额外请求。

图标 卡片左上角图标芯片 AppIcon icon={manifest.icon}
分类分组 按 category 文本分组，section 标题右侧数字为该分类的应用数 Manifest.category
状态徽标 available → 可用（青）· disabled → 已禁用（琥珀）· unavailable → 环境缺失（红），与 TaskQueue 状态色同一套色板 Manifest.status
运行方式 卡片底部左侧小标签，isQueue=true 标"队列执行"、false 标"瞬时执行"，仅做展示区分 Manifest.isQueue
运行按钮 status≠available 时按钮态变成禁用文案（已禁用 / 环境缺失），不可点击
「运行」行为 点击后调用 createTask(manifestKey) 建一条 pending 任务，并可在任务队列页跟踪；仓库里目前还没有真正执行任务的调度器/执行引擎（对照 bak 项目的 run::scheduler + run::executor 尚未移植），所以任务会一直停在 pending，等后端补上这块再联调「运行」的实际效果。“瞬时执行”（isQueue=false）的同步调用路径目前完全没实现，按钮先占位。 createTask commands::task::create_task
搜索 / 筛选 搜索框匹配 name + tags + category；两个下拉分别按 category、status 精确筛选，均为前端本地计算
